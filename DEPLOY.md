# Deployment: phase 0

The requested destinations are **Cloudflare Pages** for React and **one Render free web service** for FastAPI, with **Neon Postgres**. Deployment configuration is prepared; no external accounts, projects, credentials, or live URLs have been connected in this workspace.

## 1. Push the repository

Create a GitHub repository and push the source, including `web/package-lock.json`, `render.yaml`, and `.github/workflows/ci.yml`. Do not commit `.env`, tokens, connection strings, or virtual environments. Check that the Pulse checks workflow passes before deploying.

## 2. Create Neon Postgres

1. Sign in to Neon and create a free Postgres project.
2. Choose Singapore if available for your account, otherwise the nearest available region to the Render service. Region availability must be checked in the provider's UI.
3. Open **Connect**, select the pooled endpoint, and copy the Postgres connection string.
4. Keep TLS enabled. The application normalizes `postgresql://` to SQLAlchemy's asyncpg dialect and converts `sslmode=require` to asyncpg's `ssl=require`. The libpq-only `channel_binding` option is removed; TLS remains required. See `backend/.env.example` for the local format.

The phase 0 migration establishes only an Alembic version marker. Feature tables are intentionally introduced in later phases.

## 3. Deploy the API to Render

1. In Render choose **New → Blueprint** and connect the GitHub repository.
2. Review `render.yaml`: Python runtime, free plan, Singapore, `backend` root, `/healthz`, exactly one worker.
3. Set **DATABASE_URL** to the Neon pooled connection string. Set **ALLOWED_ORIGINS** to your final Cloudflare Pages origin, without a trailing slash. If the frontend URL is not known yet, use a temporary explicit local origin and update it in step 4.
4. JWT_SECRET, CRON_SECRET, and SALT_SECRET are generated by the blueprint but are not used by phase 0 features. Leave LLM_API_KEY unset.
5. Create the service. The build installs `requirements.lock.txt` and the local package without re-resolving dependencies; startup runs:

   ```sh
   alembic upgrade head && uvicorn app.main:app --host 0.0.0.0 --port $PORT --workers 1 --no-access-log
   ```

6. Visit `https://<your-service>.onrender.com/healthz`. Expect `{"status":"ok","service":"pulse","phase":0}`.
7. Visit `/docs`. Only health and metadata endpoints should exist.

If Render does not offer a free instance in the selected region, choose the closest available free region and update the blueprint to match. Do not silently select a paid instance.

## 4. Deploy the frontend to Cloudflare Pages

1. Open Cloudflare **Workers & Pages → Create → Pages → Connect to Git**.
2. Select the repository and your production branch.
3. Select the **Vite** framework preset. Set **Root directory** to `web`, **Build command** to `npm run build`, and **Build output directory** to `dist`.
4. Set build environment variables **NODE_VERSION=22** and **VITE_API_URL=https://<your-service>.onrender.com**.
5. Deploy. Save the returned `https://<project>.pages.dev` URL.
6. Set the API's **ALLOWED_ORIGINS** to that exact origin and redeploy the API.
7. Open the frontend and check `/`, `/welcome`, `/monitors`, `/status/acme`, search, and a hard reload on a nested route. `public/_redirects` handles React routes.

The frontend serves the phase 0 sample workspace independently of API availability. It currently uses VITE_API_URL only for the API docs link and example tracker snippet. No live fetch or cold-start recovery is claimed.

## 5. External cron: wait for phase 2

`POST /api/cron/tick` is **not implemented** in phase 0. Do not configure a cron request to a nonexistent endpoint. Once phase 2 implements and verifies it:

1. Create a free cron-job.org account and choose **Create cronjob**.
2. Set the URL to `https://<your-service>.onrender.com/api/cron/tick`.
3. Set the method to **POST**, the schedule to **every five minutes**, and the custom header `X-Cron-Secret` to CRON_SECRET. The implemented header contract must match.
4. Test it and enable failure notifications. Check actual provider limits and free-tier instance hours before relying on continuous operation.

Render may sleep when idle. Later phases will record monitor gaps and exclude them from site downtime. Neither sleeping behavior nor free-tier throughput has been measured for this scaffold.
